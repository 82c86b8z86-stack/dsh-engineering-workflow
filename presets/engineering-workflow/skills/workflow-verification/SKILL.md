# 验证收尾（Workflow Verification）

**核心原则：证据先于断言，永远。** 违反本规则的字面 = 违反其精神。

## 铁律

```
没有新鲜验证证据，就没有完成声明。
```

本次消息里没跑过那个验证命令，就不能声称它通过。

## 门函数

```
宣称任何状态或表达满意之前：

1. IDENTIFY：哪条命令能证明这个声明？
2. RUN：完整运行该命令（新鲜的、完整的）
3. READ：读全量输出、查退出码、数失败数
4. VERIFY：输出证实了声明吗？
   - 否 → 用证据陈述实际状态
   - 是 → 带证据陈述声明
5. ONLY THEN：才做声明

跳过任何一步 = 撒谎，不是验证。
```

## 常见失败（claim 对照表）

| 声明 | 需要 | 不够 |
| --- | --- | --- |
| 测试通过 | 测试命令输出：0 失败 | 上次跑过 / 「应该能过」 |
| Lint 干净 | Lint 输出：0 错误 | 部分检查、外推 |
| 构建成功 | 构建命令：退出码 0 | Lint 过了、日志看着还行 |
| Bug 已修 | 原症状测试通过 | 代码改了、假定修好 |
| 回归测试有效 | 红绿循环已验证（改回原实现必须失败） | 测试只通过一次 |
| 子 agent 完成了 | VCS diff 显示改动 + 你的独立核验 | agent 报「成功」 |
| 需求满足 | 逐行核对清单 | 测试通过 |

## 红线——STOP

- 使用「应该」「大概」「似乎」；验证前表达满意（「搞定了！」「完美！」）；没验证就提交/推送/PR；信任 agent 成功报告；依赖部分验证；「就这一次」；累了想收工。

## 合理化预防

| 借口 | 现实 |
| --- | --- |
| 「应该能过了」 | 跑验证。 |
| 「我很有信心」 | 信心 ≠ 证据。 |
| 「Lint 过了」 | Lint ≠ 编译器。 |
| 「agent 说成功了」 | 独立核验。 |
| 「部分检查够了」 | 部分证明不了任何事。 |
| 「换种说法规则就不适用了」 | 精神高于字面。 |

## 分支收尾（实现完成、全绿之后）

宣布：「I'm using the workflow-verification skill to complete this work.」

1. **验证测试**：跑项目完整套件（`npm test` / `pytest` / `go test ./...`，DSH 里用 `pwsh`/`bash`）。失败 → 报告失败并停下，菜单在绿套件之后。
2. **检测环境**：普通仓库还是 worktree；确定 base 分支（不确定就问：从哪个分支分出来的——合错 base 的代价高昂）。
3. **呈现菜单**（原文呈现，等用户选择）：

```
Implementation complete. What would you like to do?

1. Merge back to <base-branch> locally
2. Push and create a Pull Request
3. Keep the branch as-is (I'll handle it later)

Which option?
```

4. **执行选择**：
   - 合并：合并 → 在合并结果上重跑测试 → 绿了再清分支。
   - PR：推送并创建 PR，报告 URL；工作区保留给反馈迭代。
   - 保留：报告保留状态。
   - 丢弃只发生在用户明确要求时；要求确认（`Type 'discard' to confirm.`），逐字确认后才删。
5. **文档收尾**：按项目约定更新 CHANGELOG / 文档（无约定则不虚构）。
6. **Rulings 汇总**：若本任务走过 `workflow-subagents`，把账本里全部 `Ruling:` 汇总进最终消息（按序、带错误代价）——那是你替用户做的决定的唯一出口。

## 何时应用

**总是在以下之前**：任何成功/完成声明、任何满意表达、任何关于工作状态的正面陈述、提交、PR 创建、任务完成标记、进入下一任务、委派 agent。

规则适用于：原句、转述、同义词、隐含的成功、任何暗示完成/正确的交流。

## 红线（收尾特化）

| 念头 | 事实 |
| --- | --- |
| 「这次会话早些时候测试过了」 | 在你即将集成的树上跑。绿过只证明它当时跑过的那棵树。 |
| 「他显然想合并」 | 集成是用户的决定。呈现菜单，等待。 |
| 「'嗯，删了吧' 算确认」 | 只有逐字 `discard` 授权删除。 |
| 「PR 挂上了，工作区是垃圾了」 | PR 反馈在该工作区修。保留到落地。 |
| 「合并结果失败大概是 flaky」 | 合并结果失败 = 一切停下。分支与工作区原地保留，调查。 |
